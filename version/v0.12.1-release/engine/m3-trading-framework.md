## 一、框架定位

交易员（M3）面对的核心问题是：**这只券今天需要我关注吗？** 这与 L0 信号卡的设计哲学完全同构——L0 的核心不是"提供信息"，而是回答同一个问题；不需要时零认知负担滑过，需要时给出足够理由促使展开（设计哲学见《output-layered-framework.md》§3.1，本文不复制）。

**节奏定位**：M3 的决策时域为**日内-周度**，视角三问为"利率环境？信用环境？流动性环境？"——角色定义、三问与频率列以《multi-stakeholder.md》§一（六类利益相关者总览）M3 行为单一事实源，本框架不复述该表，只在三拍工作流中消费其结论。

**与 WP-M3-01 的对应关系**：本框架是工作路径 WP-M3-01（交易盯市信号卡）的方法论载体——路径定义、触发词、engine_sequence、产物清单与质量门以《work-path-registry.md》WP-M3-01 条目为单一事实源；本框架把该路径展开为可执行的盯市工作流（§二至§六）。

**编排层边界**：本框架只做工作流编排。信号卡规范、温度计档位、优先级评分、升级触发等全部数值与规则，分别归属各自单一事实源文档；本框架任何一处出现数值，均为引用入口说明，语义裁决以被引文档为准。

## 二、盯市工作流三拍

M3 盯市按"盘前-盘中-盘后"三拍运转，每拍只消费既有规范，不发明新产物。

### 2.1 盘前准备

1. **持仓清单确认**：圈定当日盯市范围（全部持仓 + 强制关注列表）。
2. **隔夜信用事件归集**：归集上一收盘至当日开盘前的公告、评级行动与违约事件，进入当日信号候选池（信号提取规则见《mosaic-engine.md》§三）。
3. **温度计读数**：读取 SRI 系统性预警温度计当前等级，作为当日全部盯市判断的系统性背景（温度计四级体系见《systemic-warning-framework.md》§三；档位语义与阈值以该文档为准，本框架不复制）。

### 2.2 盘中刷新

- 按 §三 各信号源的刷新节奏执行——日度信号源按日刷新，事件驱动信号源即时响应。
- **触发即上卡，无触发零打扰**：信号达到上卡条件（§四）才生成/更新信号卡；无触发时不推送任何东西。静默原则（含"引擎 90% 的时间应该告诉用户无事发生"的设计原则）见《output-layered-framework.md》§3.4，本框架不复制其细则。

### 2.3 盘后复盘

1. **当日信号归档**：当日上卡信号连同触发依据归档，供次日盘前与周度复盘对比。
2. **升级决策**：对当日红色（高优先级）信号逐一裁定是否升级 WP-M1-01 完整分析（升级边规则见 §六）。
3. **强制关注列表维护**：按当日复盘结论增删强制关注列表成员（列表的语义与例外推送规则见《output-layered-framework.md》§3.4）。

## 三、信号源分层与刷新节奏

盯市信号按可得性与节拍分为五层。本表是 M3 工作流的**编排定义**（哪些源、什么节拍进盯市视野），各层指标本身的分析规则仍归属各自框架文档。

| 层 | 信号源 | 示例指标 | 刷新节奏 | 数据可得性 |
|---|---|---|---|---|
| **资金面层** | 货币市场利率 | DR007 / R007 / Shibor | 日度 | 公开可得 |
| **利率层** | 收益率曲线 | 国债/国开收益率曲线变动 | 日度 | 公开可得 |
| **信用事件层** | 发行人事件 | 公告 / 违约 / 评级行动 | 即时（事件驱动） | 公开披露 |
| **系统性层** | SRI 温度计 | 温度计等级 | 仅等级变化时推送 | 引擎计算 |
| **微观结构层** | 市场微观结构 | Bid-ask spread / 做市商报价 | —（不可得） | **数据缺口** |

分层说明：

- **系统性层**的推送规则（仅等级变化时推送、状态不变不重复推送、同等级单日限频）以《output-layered-framework.md》§3.6 温度计卡片触发规则为单一事实源，本框架不复制其触发表与阈值。
- **微观结构层是诚实标注的缺口**：中国信用债市场 bid-ask spread 不披露、做市商报价不可得，交易成本因此不可知。该缺口的角色级说明以《multi-stakeholder.md》§1.2（各角色的关键数据需求）M3 行为单一事实源。缺口不静默跳过——它决定本框架的盯市只能是"信用事件 + 资金面"驱动，而非全市场微观驱动（见 §九）。
- 资金面/利率层的角色级数据需求口径同样见《multi-stakeholder.md》§1.2 M3 行（DR007/Shibor、收益率曲线、跨市场联动）。

## 四、信号→L0 卡触发决策

信号从候选池到 L0 信号卡的决策链：

```
信号候选池（§二 盘前归集 + 盘中刷新）
  → 优先级评分（评分规则见单一事实源，本文不复制）
  → 评分 >30 → 上卡（TOP3 容量约束）
  → 零信号 → 静默卡（不推送）
  → 例外：强制关注列表内标的零信号也可推送
```

1. **上卡条件**：信号优先级评分 **>30** 方进入 L0 信号卡。评分公式（紧急性×重要性×置信度）、阈值与过滤规则以《output-layered-framework.md》§六（信息优先级排序规则）为单一事实源；信号池的提取与置信度分级以《mosaic-engine.md》§三、§四为单一事实源。本框架只引用入口条件，不复制评分表。
2. **卡片容量**：每只券最多展示 **TOP3** 条信号（按优先级从高取）。信号区元素规则（严重度图标 + 一句话 + 关键数字）见《output-layered-framework.md》§3.3，本框架不复制。
3. **零信号 → 静默卡**：无任何评分 >30 信号时，降级为静默卡——不推送，但持仓列表中仍可见，评级与展望照常显示。静默卡的完整状态规范见《output-layered-framework.md》§3.4。
4. **例外条款**：用户主动加入**强制关注列表**的标的，零信号也可推送。例外条款的语义边界见《output-layered-framework.md》§3.4。

## 五、输出规范

- **L0 信号卡 = `templates/template-type19.html`**：双形态渲染——有信号卡（含 TOP3 信号区）与静默卡（无信号提示语），两形态共享同一版面骨架。**一屏可见**是硬约束：全部内容须在一屏内呈现、无需滚动（版面布局硬约束见《output-layered-framework.md》§3.2，本框架不复制其高度定义）。
- **温度计读数联动**：当 SRI 温度计等级发生变化时，在 L0 信号卡列表顶部插入一张**聚合温度计卡片**，向全部持仓用户推送系统性风险等级变动；该卡片不针对单只券。触发规则、推送策略、频率控制与个股信号卡的联动加分机制，一律以《output-layered-framework.md》§3.6 为单一事实源，本框架不复制其触发表；温度计档位语义以《systemic-warning-framework.md》§三为准。
- **产物清单**：L0 信号卡 + 温度计读数，与《work-path-registry.md》WP-M3-01 条目的 outputs 字段一致。

## 六、升级边

- **L0 红色（高优先级）信号 → 升级 WP-M1-01 完整分析**：L0 信号卡只回答"要不要关注"；一旦出现红色优先级信号，即存在需重点关注的事项，应升级为 L1/L2 深度的完整投资分析。该升级边的触发条件、目标路径与依据以《work-path-registry.md》§五（链式规则）升级触发表 L0→L1 行为单一事实源，本框架不复制。
- **L0→L1→L2 导航语义**：三层输出的定义、导航关系与"每次展开保持上下文连续"的约束，以《output-layered-framework.md》§2.2（三层之间的导航关系）为单一事实源，本框架不复述。

## 七、情景示例（匿名）

> 匿名规范：示例不出现真实公司名、不给出真实数值结论，一律用占位（某发行人 / 示例读数 / 某评级）。

### 示例一：有信号日

某发行人（某评级，展望占位）：

1. **盘前**：持仓清单确认在列；隔夜归集到该发行人一则公告事件进入候选池；温度计读数 🟡（示例读数），当日盯市带上系统性关注背景。
2. **盘中**：该公告事件经优先级评分越过上卡门槛（>30，评分规则见 §四指针），构成红色（高优先级）信号 → 触发上卡，以有信号卡形态推送，信号区按 TOP3 容量展示。
3. **盘后**：信号归档；按 §六 升级边裁定——红色信号成立，升级 WP-M1-01 完整分析；该标的保留在强制关注列表，次日盘前继续跟踪。

### 示例二：静默日

同一发行人另一交易日：

1. **盘前**：无隔夜信用事件；温度计等级无变化（示例读数维持）→ 系统性层不推送。
2. **盘中**：各信号源按节奏刷新，无任何信号评分越过上卡门槛 → 零触发。
3. **盘后**：静默卡（不推送、持仓列表可见"正常/无新信号"）；无升级事项；零打扰——当日对该发行人的全部输出就是"无事发生"。

（以上示例为匿名方法演示，不构成任何具体券种的关注或交易建议。）

## 八、质量门

盯市交付前逐项核对，全部为**指针形态**——规则本体在单一事实源文档，本框架不新设阈值：

1. **一屏可见**：信号卡全部内容是否一屏内呈现、无需滚动（版面硬约束见《output-layered-framework.md》§3.2）。
2. **零信号不推送**：无评分 >30 信号的标的是否确为静默卡、未发生推送（静默原则见《output-layered-framework.md》§3.4；强制关注列表例外同条）。
3. **温度计仅等级变化推送**：温度计卡片是否仅在等级变化时插入、同等级当日未重复推送（触发规则见《output-layered-framework.md》§3.6.1）。
4. **指针完整性**：本框架任何数值表述是否均可回溯至上述单一事实源——凡找不到出处的新阈值，一律视为漂移，删除。

## 九、诚实性与局限

- **交易成本不可知**：bid-ask spread 不披露、做市商报价不可得（微观结构层缺口，见 §三），盯市结论无法计入冲击成本与真实可成交性。
- **驱动模式受限**：在微观结构数据缺口下，本框架的盯市为**"信用事件 + 资金面"驱动**，而非全市场微观结构驱动——它能捕捉"出了什么事"，不能捕捉"市场正在怎么定价这笔事"。
- **输出性质边界**：盯市输出是"是否关注"的提示，**不构成择时建议、不构成交易建议**；红色信号的后续动作一律经由 §六 升级边进入完整分析后再行决策。
